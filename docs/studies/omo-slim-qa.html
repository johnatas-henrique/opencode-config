O que e

Plugin de orquestracao de agentes para OpenCode. Adiciona 7 especialistas + 1 opcional que trabalham sob um Orchestrator. Cada um usa um modelo diferente, equilibrando custo e qualidade.

Ideia central: "instead of forcing one model to do everything, the plugin routes each part of the job to the agent best suited for it"

Fonte: README

Instalacao

Como instalar?
bunx oh-my-opencode-slim@latest install --preset=opencode-go

Fonte: docs/installation.md

O instalador:

  • Adiciona o plugin no opencode.json
  • Gera ~/.config/opencode/oh-my-opencode-slim.json com presets
  • Desabilita agents default do OpenCode
  • Com --preset=opencode-go, ativa Observer com kimi-k2.6
E depois da instalacao?
opencode auth login
opencode models --refresh
opencode

Dentro do OpenCode: ping all agents

Fonte: README, Getting Started e Verify Your Setup

Onde fica o arquivo de configuracao?

~/.config/opencode/oh-my-opencode-slim.json — ou .jsonc (JSON com comentarios, recomendado).

Fonte: docs/configuration.md

Posso trocar os modelos que cada agente usa?

Sim. Edite o preset no JSON. Exemplo:

"opencode-go": {
  "explorer": { "model": "opencode-go/mimo-v2.5", "skills": [], "mcps": [] },
  "librarian": { "model": "opencode-go/mimo-v2.5", "skills": [], "mcps": ["websearch"] }
}

Cada agente aceita: model, temperature (0-2), variant (low/medium/high), skills (["*"] = todas), mcps (["*", "!context7"] = todas exceto context7).

Fonte: docs/configuration.md — Full Option Reference

Como desinstalar?
  1. Remove "oh-my-opencode-slim" do plugin array no opencode.json
  2. Remove ~/.config/opencode/oh-my-opencode-slim.json
  3. Remove ~/.config/opencode/skills/simplify codemap clonedeps (skills bundled)

Fonte: docs/installation.md

Fluxo de uso real

Voce abre o OpenCode e simplesmente descreve a task. Exatamente como faz hoje.

1. Voce digita: "Adiciona autenticacao Google no backend com Fastify"
2. O Orchestrator analisa e decide o que fazer. Se precisar explorar o codigo existente, chama o Explorer (automatico, voce nao ve o comando).
3. Explorer vasculha, retorna contexto. Orchestrator avalia. Se precisar de decisao arquitetural, chama Oracle.
4. Com plano definido, Orchestrator chama Fixer pra implementar.
5. Fixer implementa, testes rodam, Orchestrator mostra resultado pra voce.

Voce so ve o resultado final — a delegacao entre agentes acontece em child sessions, transparente pro seu terminal.

Features detalhadas — alem da orquestracao

Abaixo, cada feature do omo-slim comparada com o que um template config (AGENTS.md + jsonc) consegue replicar.

1. Interview (/interview)

omo-slimTemplate config
Abre navegador local com Q&A, gera spec markdown, suporta dashboard multi-sessao. Config: interview.port, interview.maxQuestions.Impossivel. Requer servidor web + UI no navegador + escrita de arquivos.

Digita /interview build a kanban app, abre localhost com perguntas, responde no navegador, gera spec markdown no repositorio.

Link: docs/interview.md — "Start a new interview: /interview build a kanban app"

2. Codemap

omo-slimTemplate config
Skill com codigo (codemap.mjs). Gera .slim/codemap.json com hash tracking + codemap.md por pasta + change detection.Parcial. Pode instruir o agente a documentar arquitetura, mas sem hash tracking nem deteccao automatica de mudancas.

Nao e hook — e codigo executavel. O script seleciona arquivos usando LLM judgment, cria hashes pra detectar mudancas, gera templates de documentacao.

Link: docs/codemap.md — "creates .slim/codemap.json for change tracking"

3. MCPs built-in (websearch, context7, grep_app)

omo-slimTemplate config
Ja vem com 3 MCPs configurados. Permissao granular por agente (Explorer sem MCPs, Librarian com websearch+context7).Replicavel no jsonc. Adiciona no opencode.jsonc e controla permissao via agent.<name>.permission.

Se ja tem context7 no jsonc: (a) desliga no omo-slim com disabled_mcps: ["context7"], ou (b) deixa omo-slim gerenciar e remove do jsonc.

Link: docs/mcps.md — tabela "Default Permissions Per Agent"

4. Skills (simplify, codemap, clonedeps)

omo-slimTemplate config
Skills injetadas no system prompt do agente. Atribuicao ativa via presets...skills. Se nao esta no array, o agente nao carrega.Replicavel parcialmente. Escreve instrucoes no AGENTS.md. OpenCode nativo carrega skills on-demand via skill tool — sem "atribuicao forcada".

Nova skill instalada em ~/.config/opencode/skills/: precisa adicionar no array skills do agente no preset. Sem isso, omo-slim nao usa.

Link: docs/skills.md + opencode.ai/docs/skills

5. Todo Continuation

omo-slimTemplate config
Auto-continua o Orchestrator quando para com todos incompletos. Cooldown 3s, safety gates, Escx2 aborta. Opt-in (desabilitado por padrao).Exclusivo de plugin.

Link: docs/todo-continuation.md

6. Session Management

omo-slimTemplate config
Lembra child sessions recentes (exp-1, fix-2). Na proxima delegacao relacionada, reusa em vez de criar nova. Em memoria, some no restart.Exclusivo de plugin.

Util porque: 1a chamada → Explorer vasculha 20 arquivos. 2a chamada → reusa child session, Explorer ja tem os 20 arquivos no contexto. Economiza tokens.

Link: docs/session-management.md

7. Fallback (model failover)

omo-slimTemplate config
Se modelo da timeout/erro, tenta proximo da lista. Configuravel por agente via fallback.chains.Exclusivo de plugin.

Se tem poucos modelos (deepseek-v4-flash, mimo-v2.5), fallback nao agrega. Pode pular.

8. Prompt Overriding

omo-slimTemplate config
Arquivos ~/.config/opencode/oh-my-opencode-slim/{agent}.md sobrescrevem prompt built-in. Suporte a preset (pastas por preset).Replicavel no jsonc. agent.<name>.prompt permite custom prompt.

Link: docs/configuration.md#prompt-overriding

9. Custom Agents

omo-slimTemplate config
Define agentes com model, prompt, orchestratorPrompt (ensina o Orchestrator QUANDO delegar), skills, mcps.O coracao dos template configs. Supersimple (#30), hossainemruz (#29) fazem isso. Sem "delegation rules" (orchestratorPrompt).

Link: docs/configuration.md#custom-agents

10. Multiplexer (Tmux/Zellij)

omo-slimTemplate config
Paineis automaticos no terminal mostrando cada child session em tempo real.Exclusivo de plugin.

Fluxo: instala tmux, ativa no json: multiplexer: { type: "auto" }, inicia opencode --port 4096 dentro do tmux. Quando orquestrador delega, novo painel abre com o agente trabalhando. Navega com Ctrl+B+setas, zoom Ctrl+B+z.

Link: docs/multiplexer-integration.md

Perguntas respondidas

/goal e necessario pra delegar tasks pros outros agentes?

Nao. O Orchestrator delega automaticamente baseado na task, independente de /goal.

O /goal e opcional — so pinta um lembrete do "porque" no contexto. Fonte: docs/session-goal.md

Posso trabalhar em 2 tasks ao mesmo tempo?

Nao na V1. Delegacao e sequencial — Orchestrator chama Explorer, espera, depois Fixer.

V2 Beta muda: Orchestrator vira scheduler, dispara em background. Beta: bunx oh-my-opencode-slim@beta install + variavel experimental.

Fonte: README, V2 Background-Orchestration Beta

O que acontece quando o Orchestrator chama um agente?

Cria uma child session — sessao separada com modelo e permissoes daquele agente. Executa, retorna, encerra. Fonte: docs/multiplexer-integration.md

Como desativar pra testar sem conflito com meus plugins?

Comenta no opencode.jsonc: // "oh-my-opencode-slim". Reinicia OpenCode. Fonte: docs/installation.md

O omo-slim e diferente de um template config?

Sim. Template config = texto. omo-slim = plugin runtime com permissoes reais, MCPs gerenciados, session tracking, fallback, continuation, multiplexer. Coisas que texto nao faz.
