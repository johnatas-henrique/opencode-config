O que é

Uma skill (não plugin) que ensina o agente a planejar em 3 arquivos durante tasks complexas. Não modifica seu opencode.jsonc — é só um arquivo de instrução em ~/.config/opencode/skills/planning-with-files/SKILL.md.

Baseada nos Manus Principles (a empresa de context engineering que o Meta adquiriu por $2B).

Fonte: README

Instalação

Como instalar?

Global (recomendado):

bunx skills add OthmanAdi/planning-with-files --skill planning-with-files -g

Isso coloca a skill em ~/.config/opencode/skills/planning-with-files/SKILL.md

Projeto:

bunx skills add OthmanAdi/planning-with-files --skill planning-with-files

Coloca em .opencode/skills/planning-with-files/SKILL.md

Fonte: docs/opencode.md

Como verificar se está instalado?
ls -la ~/.config/opencode/skills/planning-with-files/SKILL.md

Fonte: docs/opencode.md — Verification

Preciso ler a skill manualmente toda vez?

No OpenCode, sim — skills não são carregadas automaticamente como no Claude Code. Você precisa:

cat ~/.config/opencode/skills/planning-with-files/SKILL.md

E depois descrever a task. O agente lê as instruções e segue o padrão.

Alternativas:

  • Com Superpowers plugin: usa use_skill tool com skill_name: "planning-with-files" — automático
  • Com oh-my-openagent (61k stars): configura no oh-my-opencode.json e o plugin carrega automaticamente
  • Com omo-slim: agentes com "skills": ["*"] podem ler a skill, mas não há UI dedicada — você precisa pedir explicitamente

Fonte: docs/opencode.md

Como funciona — os 3 arquivos

A skill instrui o agente a criar e manter 3 arquivos durante qualquer task complexa:

.opencode/plans/<nome-da-task>/
├── task_plan.md    ← Fases + checkboxes de progresso
├── findings.md     ← Pesquisas e descobertas
└── progress.md     ← Log da sessão e resultados de teste

task_plan.md

Contém: goal, fases (3-7) com checkboxes, decisões importantes, erros encontrados.

Atualiza quando: inicia task, completa fase, toma decisão, encontra erro.

O hook PreToolUse (no Claude Code) lê este arquivo antes de toda operação Write/Edit/Bash — força o agente a não desviar do plano.

findings.md

Contém: pesquisas, descobertas, decisões técnicas com rationale, recursos úteis.

Atualiza quando: descobre algo novo, após 2 operações de view/browser (2-Action Rule), toma decisão técnica.

progress.md

Contém: log de ações, resultados de teste, erros com timestamp.

Atualiza quando: inicia fase, completa fase, roda testes, encontra erro, retoma após pausa.

ArquivoContémCriado quando
task_plan.mdGoal, fases, checkboxes, decisões, errosInício da task
findings.mdPesquisa, descobertas, decisões técnicasInício da task
progress.mdLog de ações, testes, erros com timestampInício da task

Fluxo de uso real

Os 5 passos

Passo 1 — Carregar a skill e descrever a task
Você lê a skill ou pede pro agente usar o padrão: "Use planning-with-files pra planejar. Quero adicionar autenticação Google."
Passo 2 — Agente cria os 3 arquivos
O agente (seguindo a skill) cria task_plan.md, findings.md, progress.md em .opencode/plans/auth-google/ com fases iniciais baseadas no que você descreveu.
Passo 3 — Trabalhar e documentar
Enquanto executa, o agente atualiza os arquivos: pesquisa → findings.md, decisão → findings.md, fase completa → task_plan.md, erro → ambos.
Passo 4 — Re-ler antes de decisões
A skill instrui: antes de Write/Edit/Bash, releia task_plan.md. No OpenCode isso é textual (agente pode ignorar). No Claude Code, hooks forçam.
Passo 5 — Completar
Verifica se todas as fases estão complete. Entrega resultado. Arquivos ficam salvos.

Fonte: docs/quickstart.md

Limitação importante: O plano é gerado ANTES de explorar o código. A qualidade do plano inicial é baseada em suposição. O agente descobre a realidade só depois, durante a execução das fases.

Perguntas respondidas

O plano é gerado antes de ler o código existente. Isso não é um problema?

Sim, é um problema real. A skill manda criar o plano no início, antes de explorar. O plano inicial é baseado em suposição.

Na prática, o agente cria o plano, depois descobre a realidade ao executar as fases, e atualiza o plano. Mas o plano inicial é fraco.

O fluxo ideal seria: explorar → planejar → implementar. A skill faz: planejar → implementar (descobrindo durante).

O que é Session Recovery?

Quando o contexto enche e você dá /clear, o agente perde tudo. Session Recovery é um script da skill que tenta recuperar automaticamente:

  1. Lê o session store do IDE
  2. Encontra quando os planning files foram atualizados
  3. Extrai a conversa perdida depois da última atualização
  4. Mostra catchup report pro agente: "Você estava na fase X, já fez Y, falta Z"

No OpenCode, isso funciona parcialmente. O session store do OpenCode usa SQLite em ~/.local/share/opencode/opencode.db. Se o SQLite query falhar, o workaround é ler os 3 arquivos manualmente.

Fonte: docs/opencode.md — Known Limitations

O que é a 2-Action Rule?

A skill impõe: após cada 2 operações de view/browser/search, o agente deve atualizar findings.md.

Exemplo:

  1. WebSearch → nota resultado (1ª)
  2. WebFetch → precisa atualizar findings.md AGORA (2ª)
  3. Read file → nota resultado
  4. Grep search → precisa atualizar findings.md AGORA

Objetivo: evitar que pesquisa seja perdida quando o contexto enche.

Fonte: docs/workflow.md

Esse enforcement funciona no OpenCode?

Só textualmente. A skill diz "faça X", mas o agente pode ignorar. Os hooks (PreToolUse, PostToolUse, Stop) que realmente forçam o comportamento são nativos do Claude Code, não do OpenCode.

O OpenCode não tem sistema de hooks igual ao Claude Code. A skill funciona, mas depende do agente seguir instrução — que, como você bem observou, é frágil.

Fonte: docs/workflow.md (hooks listados apenas para Claude Code)

O que é o Hash Attestation (v2.37)?

O comando /plan-attest gera um SHA-256 do task_plan.md. Depois disso, os hooks rejeitam qualquer edição no arquivo se o hash não bater. Impede que o agente ou você modifique o plano sem autorização explícita.

Fonte: README, changelog v2.37

O que acontece com task_plan.md depois que a task termina?

Fica salvo permanentemente em .opencode/plans/<task-name>/. Não é deletado automaticamente.

Você pode revisar depois o que foi feito, recuperar contexto pra tasks similares, ou simplesmente ignorar.

Quantos arquivos posso ter?

Quantos quiser. A skill suporta plan isolation (v2.36) — diretórios separados por task:

.opencode/plans/
├── auth-google/
│   ├── task_plan.md
│   ├── findings.md
│   └── progress.md
├── refactor-api/
│   ├── task_plan.md
│   ├── findings.md
│   └── progress.md
└── fix-login-bug/
    ├── task_plan.md
    ├── findings.md
    └── progress.md

Para trocar o plano ativo: ./scripts/set-active-plan.sh <nome> (se tiver o repositório clonado). Fonte: docs/quickstart.md
